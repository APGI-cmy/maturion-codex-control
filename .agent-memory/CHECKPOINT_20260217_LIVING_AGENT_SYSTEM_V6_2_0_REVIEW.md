## CRITICAL PATTERNS FROM THIS SESSION

### Pattern 1: Living Agent System v6.2.0 Alignment

**What it is**: Migration from basic agent files to comprehensive 4-phase canonical architecture.

**Key Changes**:
- **BEFORE**: Simple agent file (~17-19K chars, basic instructions)
- **AFTER**: Comprehensive contract (~26-28K chars, 4-phase architecture)

**What MUST be included**:
- Phase 1: Preflight (~220 lines) - Identity, self-modification prohibition, RAEC examples, canonical references
- Phase 2: Induction (~30 lines) - Task loading protocol, halt conditions
- Phase 3: Build (~25 lines) - Zero test debt, domain-specific guidance
- Phase 4: Handover (~90 lines) - Completion checklist, PREHANDOVER_PROOF template

**What CANNOT be removed** (from session-handover-20260212):
- LOCKED sections (enforcement mechanisms)
- Canonical references (traceability)
- Step-by-step protocols (actionable guidance)
- YAML frontmatter context (bindings, scope, authority)

### Pattern 2: RAEC Operating Model (Execute-Only)

**What it is**: Builder agents operate in **Execute-Only mode** (not advisory, not consultative).

**Behavioral Examples** (from PR #777 review):

❌ **WRONG**: Traditional Coding Agent
- Start coding immediately → 80% pass acceptable → Push partial work
- **Why Wrong**: Violates architecture-first, zero-test-debt, no evidence

✅ **RIGHT**: Builder Execution Model
1. **REVIEW**: Verify architecture frozen → Verify RED tests exist
2. **EXECUTE**: Implement per architecture → Fix ALL failures
3. **VERIFY**: 100% GREEN → Generate evidence
4. **ESCALATE**: If unclear → HALT → Ask FM

**Constitutional Rule**: 297/300 = FAILURE (100% GREEN is non-negotiable)

### Pattern 3: Character Count Management

**Constraints**:
- <15K: GitHub agent file size limit (some repos)
- <25K: Optimal size (balance completeness vs load time)
- <30K: Blocking limit (agent won't load beyond this)

**Balance Strategy** (from session-handover-20260212):
- **MUST include**: LOCKED sections, canonical references, protocols, YAML
- **CAN compress**: Redundant text, verbose examples, duplicate explanations
- **CANNOT remove**: Living Agent System requirements, gold standard mappings

**This Session**: All builder contracts 26-28K (slightly over 25K optimal but well under 30K blocking) = ✅ ACCEPTABLE
